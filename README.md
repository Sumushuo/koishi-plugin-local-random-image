# koishi-plugin-local-random-image

一个面向 Koishi 4 的本地图库插件：将图库根目录下的一级文件夹名作为触发词，收到完全匹配的消息时，从对应图包随机发送一张图片；也可以通过“加图”命令，把当前消息或引用消息中的图片保存到指定图包。

插件以本地文件系统为存储，不依赖数据库，也不会为普通聊天中的未命中内容发送提示。

## 功能概览

- **文件夹即触发词**：例如发送 `猫猫`，随机发送 `猫猫` 文件夹中的一张图片。
- **静默匹配**：触发词不存在、图包为空、处于冷却期或消息不符合匹配规则时，交给后续中间件处理。
- **消息加图**：支持 `/加图`、`添加图片`、`存图` 及多种全角/半角前缀。
- **直接附图与引用取图**：可从当前消息、引用消息、适配器消息查询结果以及 OneBot 原始消息中提取图片或表情。
- **自动新建图包**：目标图包不存在时，在图库根目录下新建同名一级文件夹。
- **可选管理员限制**：可以只允许群主或管理员使用加图功能。
- **独立冷却**：可按“频道 + 图包”限制触发频率，避免同一图包刷屏。
- **路径防护**：拒绝路径分隔符、`..`、空字节和 Windows 非法文件名字符，并再次检查目标是否位于图库根目录内。
- **跨平台本地发送**：通过标准 `file://` URL 发送本地图片，兼容 Windows 与类 Unix 路径。

## 运行要求

- Koishi `^4.15.0`
- 能访问图库目录的文件系统权限
- 如需保存网络图片，运行环境需要能够访问对应图片地址
- 推荐使用带原生 `fetch` 的现代 Node.js；当原生下载失败时，插件还会尝试 Koishi 的 `ctx.http`

不同聊天平台对本地文件、图片大小、GIF 或表情资源的支持程度可能不同，最终发送效果取决于所使用的适配器和平台限制。

## 安装

本仓库尚未假定已经发布到 npm。可以克隆仓库后，以本地依赖的方式安装到 Koishi 实例。

```bash
git clone https://github.com/sumushuo/koishi-plugin-local-random-image.git
cd koishi-plugin-local-random-image
npm install
```

然后在 Koishi 实例的 `package.json` 中加入本地依赖。以下为 Windows 示例，JSON 中建议使用正斜杠：

```json
{
  "dependencies": {
    "koishi-plugin-local-random-image": "file:D:/path/to/koishi-plugin-local-random-image"
  }
}
```

重新安装实例依赖并启动 Koishi 后，在控制台启用 `local-random-image`，至少填写 `baseDir`。

> 包的运行入口是仓库根目录下的 `index.js`，正常使用不要求先编译 TypeScript。`src/index.ts` 用于开发和类型检查，`npm run build` 会将其编译到 `lib/`。

## 快速开始

假设 `baseDir` 配置为 `D:/Images`：

```text
D:/Images/
├── 猫猫/
│   ├── 01.jpg
│   ├── 02.png
│   └── 03.webp
├── 柴犬/
│   ├── 01.jpg
│   └── 02.gif
└── 早安/
    └── 1.png
```

发送以下消息：

```text
猫猫
```

插件会从 `D:/Images/猫猫/` 中随机挑选一张符合扩展名配置的图片发送。

触发词只匹配 `baseDir` 的**一级子文件夹**，不会递归查找更深层目录；图片候选也只读取该图包目录的当前层级。

## 配置项

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `baseDir` | `string` | 无，必填 | 本地图库根目录，推荐填写完整路径，例如 `D:/Images` 或 `D:\\图库`。相对路径会按 Koishi 进程的工作目录解析。路径必须已存在；加图功能只会创建其下的图包，不会自动创建根目录。代码只预检路径是否存在，若它不是目录，后续读取会失败并进入错误处理。 |
| `extensions` | `string[]` | `['.jpg', '.jpeg', '.png', '.gif', '.webp', '.bmp']` | 随机发送时允许匹配的文件扩展名。比较时不区分大小写；配置值应包含开头的点，例如 `.png`。该配置不限制加图时的下载来源。 |
| `caseInsensitive` | `boolean` | `true` | 是否忽略触发词与图包文件夹名的大小写差异；加图时也会用相同规则复用已有文件夹的实际名称。 |
| `cooldown` | 非负整数 | `0` | 同一频道内、同一图包的触发冷却秒数。`0` 表示不限制。没有 `channelId` 的会话不执行冷却判断。 |
| `enableAddImage` | `boolean` | `true` | 是否注册并识别“加图”“添加图片”“存图”功能。关闭后仅保留关键词随机发图。 |
| `adminOnly` | `boolean` | `false` | 是否仅允许群主或管理员加图。只在存在 `channelId` 时检查适配器上报的成员角色 `owner`/`admin`；这不是 Koishi `authority` 数值权限检查。 |

配置示例：

```yaml
plugins:
  local-random-image:
    baseDir: D:/Images
    extensions:
      - .jpg
      - .jpeg
      - .png
      - .gif
      - .webp
      - .bmp
    caseInsensitive: true
    cooldown: 10
    enableAddImage: true
    adminOnly: false
```

实际配置键会因 Koishi 配置文件中的插件实例名而异，推荐直接在 Koishi 控制台填写。

## 关键词发图规则

插件会先从消息中移除引用标签、@ 标签、其他消息元素标签以及零宽字符，再对剩余文本执行匹配。

只有同时满足以下条件时，消息才会触发随机发图：

1. 净化后的整条消息与某个一级图包文件夹名完全匹配；不会进行包含、前缀或模糊匹配。
2. 文本为单行，长度不超过 50 个字符。
3. 文本不以 `/`、`!`、`／` 或 `！` 开头，以免抢占其他命令。
4. 文本不含 `/`、`\\`、`..`、空字节或 `:` 等路径相关内容。
5. 图包内至少存在一个扩展名被 `extensions` 允许的条目。
6. 当前“频道 + 图包”没有处于配置的冷却期。

未命中图包、根目录不存在、图包为空或目录读取失败时，插件不会向用户发送额外消息；读取异常会写入日志，然后把消息交给后续中间件。

冷却记录保存在内存中，插件重载或进程重启后会清空。不同图包拥有独立冷却，同一图包在不同频道也互不影响。时间戳会在匹配到图包后、读取候选文件和实际发送之前写入；因此图包为空、读取失败或发送失败也可能消耗本次冷却。当前实现不会主动清理 Map 中的旧键，频道和图包组合极多的长期实例应留意其内存增长。

## 加图功能

### 命令与别名

标准写法：

```text
/加图 猫猫
```

同义命令：

```text
/添加图片 猫猫
/存图 猫猫
```

为了兼容不同平台的消息排版，中间件还会识别没有前缀，或以 `/`、`!`、`！`、`／`、`、` 开头的 `加图`、`添加图片`、`存图`。例如：

```text
加图 猫猫
！存图 猫猫
、添加图片 猫猫
```

中间件兼容路径会把命令后的第一个非空白片段作为图包名，因此推荐使用不含空格的图包名，以获得跨适配器的一致行为。

### 使用方式

可以在命令消息中直接附带一张或多张图片：

```text
/加图 猫猫 + 图片
```

也可以回复一条包含图片、QQ 表情或其他受支持图片元素的消息：

```text
回复含图消息：/加图 猫猫
```

插件会先递归扫描当前命令消息的元素树；部分适配器会把引用内容作为其中的子元素，因此这一步也可能直接找到被引用图片。仍未找到时，插件才继续通过引用对象和消息查询接口取图。找到的重复地址会去重，然后逐张下载保存。

### 支持提取的消息元素

插件会递归查找以下元素类型：

- `img`
- `image`
- `mface`
- `market-face`
- `bface`

图片地址可来自元素的 `src`、`url`、`file`、`proxy` 等字段。引用消息取图还包含以下兜底：

1. 引用元素自身的子元素；
2. `session.quote` 中的元素或 HTTP(S) 地址；
3. 适配器的 `bot.getMessage()` 查询结果；
4. OneBot 适配器的 `internal.getMsg()` 原始消息段。

后两项依赖适配器是否实现相应接口，因此不能保证每个平台都可用。

### 支持读取的图片源

保存图片时支持：

- `base64://...`
- `data:image/...;base64,...`
- `file://...` 本地文件 URL
- Windows 绝对路径，例如 `D:\\cache\\image.png`
- 以 `/` 开头的类 Unix 绝对路径
- `http://` 与 `https://` 网络地址

网络图片优先使用原生 `fetch` 下载；失败或响应不成功时，会尝试 Koishi `ctx.http`，其请求超时为 15 秒。各图片独立处理，单张失败不会阻止其余图片继续保存。

> 插件信任聊天适配器提供的图片来源。它不会对下载体积、响应内容类型或远程地址做额外白名单校验，原生 `fetch` 也没有单独设置超时。请只在可信的 Koishi 实例与适配器中启用加图；如机器人开放在不受信任的环境，建议开启 `adminOnly`，并在网络层限制不必要的内网访问，以降低服务端请求伪造和大文件占用内存等风险。

### 保存格式与文件名

插件根据文件二进制特征识别以下格式：

- JPEG
- PNG
- GIF
- WebP
- BMP

无法识别或不足 4 字节时默认以 `.jpg` 保存；代码不会进一步解码验证内容确实是图片。文件名格式为：

```text
Image_<毫秒时间戳>_<0-999随机数>.<扩展名>
```

例如：

```text
Image_1760000000000_328.png
```

写入使用毫秒时间戳和 `0-999` 随机尾号，不会预先检查重名；如果同一毫秒内生成完全相同的文件名，已有同名文件会被覆盖。常规聊天流量下概率较低，但批量高并发接入时应了解这一边界。

成功保存至少一张图片后，机器人回复：

```text
已添加 2 张图片到图包：猫猫
```

如果目标图包不存在，插件会先在 `baseDir` 下创建它。若部分图片失败，日志会分别记录失败项，回复中的数字仅统计成功保存的图片。

## 权限与路径安全

### 加图权限

`adminOnly: true` 时，插件会检查群成员角色中是否包含 `owner` 或 `admin`，不满足时回复：

```text
抱歉，当前仅限管理员可以使用加图功能。
```

角色信息由聊天适配器提供。如果适配器没有提供相应角色，群内用户不会通过检查。当前实现只在会话具有 `channelId` 时执行此项限制；部署者仍应结合平台权限和机器人可访问范围进行控制。

### 目标目录限制

加图时，图包名会先移除首尾包裹符号和零宽字符，并拒绝以下内容：

- `/`、`\\`、`:`、`*`、`?`、`\"`、`<`、`>`、`|`
- 空字节
- `..`

生成目标路径后，插件还会检查其直接父目录必须是解析后的 `baseDir`，因此加图只能写入图库根目录下的一级图包。

关键词触发路径也会进行独立的字符过滤与相对路径检查。请注意，这些检查保护的是**词法上的目标图包路径**，没有调用 `realpath` 检查符号链接；如果图库内存在指向根目录外部的目录链接，读取或写入仍可能越过 `baseDir`。保存来源也可能是适配器返回的任意本地绝对路径，因此应只在受控图库和可信适配器环境中使用。

另外，随机发图只按名称扩展名筛选候选项，没有再检查候选是否为普通文件或实际图片。请勿在图包中放置伪装成图片扩展名的目录或符号链接。关闭 `caseInsensitive` 后，特殊触发词 `.` 按 Node.js 路径语义可能指向 `baseDir` 本身，因此也不要将 `.` 作为图包名或对外可用触发词。

## 错误处理与日志

关键词随机发图以“不打扰聊天”为原则：大多数不匹配或无法发送的情况会静默交给后续插件；文件系统读取、发送失败等异常会写入 `local-random-image` 日志。

加图属于显式操作，会向用户返回可理解的错误信息，包括：

- 未提供图包名；
- 图包名含非法字符；
- `baseDir` 不存在；
- 没有检测到图片；
- 图包创建失败；
- 所有图片均下载失败。

常见日志还包括自动新建图包、下载进度、单张保存失败、引用消息获取失败以及关键词命中的图片文件名。

## 常见问题

### 发送文件夹名后没有反应

依次检查：

1. `baseDir` 是否为已存在的绝对路径；
2. 目标图包是否是 `baseDir` 的一级子文件夹；
3. 消息是否只有文件夹名，且不超过 50 个字符；
4. 图包内文件扩展名是否包含在 `extensions`；
5. 当前频道与图包是否处于冷却期；
6. Koishi 进程是否有读取权限；
7. 平台适配器是否允许发送本地 `file://` 图片。

### 加图提示未检测到图片

适配器可能没有把图片暴露为插件支持的元素字段，也可能无法查询引用消息。可以先尝试在命令消息中直接附图；OneBot 环境还应确认适配器实现了消息查询接口。

### 网络图片下载失败

确认 Koishi 运行环境可以访问图片地址，图片链接没有过期，且远端没有强制登录、防盗链或证书问题。插件会先使用浏览器风格请求头尝试原生下载，再回退到 `ctx.http`，但并不能绕过平台鉴权。

### GIF 或表情保存后无法发送

插件可以识别并保存 GIF，也会尝试提取多种表情元素，但平台可能提供临时地址、专有编码或限制机器人重新上传。请结合适配器日志定位具体失败阶段。

## 开发与校验

安装开发依赖：

```bash
npm install
```

编译 TypeScript 源码并生成声明文件：

```bash
npm run build
```

检查当前实际入口 `index.js` 的 JavaScript 语法：

```bash
npm run check
```

请注意，当前 `check` 脚本等价于 `node --check index.js`；它不会替代 TypeScript 编译。修改行为时应同步维护 `index.js` 与 `src/index.ts`，并同时执行 `npm run build` 和 `npm run check`。
